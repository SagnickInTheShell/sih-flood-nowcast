# Data Sources

| Dataset | Real or Synthetic | Source / generation method |
|---|---|---|
| Ward elevation (DEM) | **Synthetic** (default, `PILOT_MODE=synthetic`) | Deterministic: base slope 45m->38m NW->SE + fractal value noise (+/-1.5m, seed=42) + a carved -2m depression along an NE->SW spline. See `backend/app/gis/synthetic_ward.py`. |
| Ward elevation (DEM) | Real (`PILOT_MODE=real`) | SRTM 1 Arc-Second Global, via USGS EarthExplorer (https://earthexplorer.usgs.gov/) -- requires a free account. See `scripts/download_srtm.py`. |
| Road network | **Synthetic** (default) | Deterministic 8x8 orthogonal grid + 2 diagonal arterials, seed=42. `backend/app/gis/synthetic_ward.py`. |
| Road network | Real | OpenStreetMap, via the `osmnx` library's Overpass API wrapper (`ox.graph_from_bbox`, network_type="drive"). `backend/app/gis/real_ward.py`. |
| Storm drain tagging | **Synthetic** (default) | ~30% of road edges randomly tagged (seeded RNG) as drain-carrying, guaranteed single-connected-component; 4 major junctions placed near the depression's low points. `backend/app/gis/synthetic_ward.py`. |
| Storm drain tagging | Real | # ASSUMPTION: approximated as "runs near an OSM-mapped waterway" (`waterway=*` tag via Overpass) -- OSM drainage/storm-drain data is inconsistent/incomplete in most Indian cities; see `docs/JUDGE_QA.md`. Real deployment needs manually curated municipal drain records. |
| Land use / SCS Curve Number | **Synthetic** (default) | Deterministic zoning: residential (CN=75) default, commercial/paved along the 2 arterials (CN=90), green space/park near the drainage depression (CN=55). `backend/app/gis/synthetic_ward.py`. |
| Land use / SCS Curve Number | Real | # ASSUMPTION: flat CN=75 ("residential, average condition") everywhere -- no licensed LULC raster wired in for the prototype. Replace with a real land-use raster before operational use. |
| Drain pipe diameters | Synthetic + Real | # ASSUMPTION: 450mm (residential) / 900mm (arterial), Manning's n=0.013 (concrete) -- not measured for any real ward, configurable via `.env` (`DRAIN_DIAMETER_RESIDENTIAL_MM`, `DRAIN_DIAMETER_ARTERIAL_MM`, `MANNINGS_N_CONCRETE`). |
| Critical infrastructure (hospital/fire/shelter) | **Synthetic** (default) | Fixed placeholder coordinates within the synthetic grid, clearly labeled "Ward Alpha ...". `backend/app/gis/synthetic_ward.py`. |
| Critical infrastructure | Real | OpenStreetMap, `amenity=hospital`/`amenity=fire_station`/`emergency=shelter` tags via `osmnx.features_from_bbox`. |
| Rainfall intensity / duration | Neither -- direct input | User-provided (demo scenario preset or live slider). A real deployment would source this from IMD/NCMRWF's short-range nowcast products; that integration is **not implemented** in this prototype. |
| GNN training labels | **Synthetic** (always) | Generated by the physics baseline (`app/ml/physics_baseline.py`), sweeping rainfall intensity in [10,20,30,40,60,80,100,120] mm/hr x duration in [30,60,90,120] min. Never presented as observed real-world flooding. |
| Historical flood event (backtest) | **None shipped** | `app/ml/backtest.py` ships one stub event with every field null/"TODO" -- no historical flood is invented. See "Adding a real historical event" below. |

## Adding a real historical event for backtesting

`GET /api/backtest/{event_id}` returns `501` until a real event is added.
To add one:

1. Find a documented flood event for your target ward (e.g. a municipal
   disaster-management report, a news report with a specific date/location,
   or IMD rainfall records) with a source URL.
2. Add a `HistoricalEvent` to `backend/app/ml/backtest.py`'s `EVENTS` dict
   with real `date`, `location_note`, `rainfall_timeseries_mm_hr`,
   `reported_flooded_streets`, and `source_url` values.
3. `run_backtest()` is already fully wired to run it through the same
   prediction pipeline used for live nowcasting.

## Adding a real pilot ward

1. Pick a bounding box (`min_lon,min_lat,max_lon,max_lat`) for your target
   ward (~2km x 2km recommended, matching the synthetic ward's scale).
2. Set `PILOT_MODE=real` and `REAL_WARD_BBOX=<your bbox>` in `.env`.
3. Run `python scripts/download_srtm.py --bbox <your bbox>` and follow its
   printed instructions (requires a free USGS EarthExplorer account).
4. Restart the backend -- `RealWardProvider` will pull roads/critical
   infrastructure from OpenStreetMap live and read the DEM tile from disk.
